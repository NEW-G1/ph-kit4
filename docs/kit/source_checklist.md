원천: `bigquery-public-data.covid19_nyt` (리전: `US`)

## 확인 항목

- [x] **데이터 소유자 승인**: AI(`ai-builder`)가 이 원천의 스키마와 집계 조회 결과를 읽는다는 것을 데이터 소유자가 승인했다. 공개·합성 원천이 아니면 고객사 실명·개인정보·대외비가 들어 있지 않은지 함께 확인했다
  - 승인한 사람(역할 코드): 공개 데이터, 요청자 확인
- [x] **개인정보 검토**: 새 원천의 컬럼을 검토해 `docs/architecture/pii_columns.md`의 표를 다시 쓰고 "검토한 원천" 줄을 이 원천으로 바꿨다. 개인 식별 컬럼이 없으면 `(없음)` 행을 명시했다
  - 후보 찾기는 인터뷰의 고정 조회(원천 `INFORMATION_SCHEMA.COLUMNS` 컬럼 이름, 데이터 값 조회 없음)를 쓸 수 있다. 확정은 사람이 한다
  - 검토 결과: 4개 테이블(`us_counties`, `us_states`, `excess_deaths`, `mask_use_by_county`) 29개 컬럼을 이름 기준으로 검토했고 개인 식별 컬럼은 없다. `pii_columns.md`에 `(없음)` 행을 두고 "검토한 원천"을 이 원천으로 바꿨다(2026-11-13, 요청자 확정)
- [ ] **리전 일치**: `ai_dev`와 운영 데이터셋(`datasets`)이 원천과 같은 리전에 있다. `source.location`에 그 리전을 적었다
  - 확인 결과: 원천 데이터셋과 4개 테이블은 모두 `US`이고 `source.location`도 `US`다. `ai_dev`와 운영 데이터셋의 리전은 아직 조회하지 않아 이 칸은 비워 둔다
  - 사다리는 첫 쿼리 전에 `ai_dev` 리전을 조회해 다르면 멈춘다. 운영 데이터셋 리전은 사다리가 보지 않는다
- [x] **원천 테이블 크기**: 쓸 테이블마다 한 쿼리가 읽는 양이 500 MB 이하이거나, 날짜 파티션이 있어 하루치만 읽을 수 있다
  - 테이블별 크기(dry-run 바이트 또는 테이블 정보): 4개 모두 일반 테이블(뷰 아님), 날짜 파티션·클러스터링 없음. 전체 컬럼 dry-run 기준 `us_counties` 163,276,345 B(3,258,152행), `us_states` 2,418,131 B(61,942행), `excess_deaths` 510,624 B(7,258행), `mask_use_by_county` 147,674 B(3,142행). 모두 500 MB 이하이므로 contract `load.mode`는 `incremental`이 아니라 전체 적재를 쓴다
  - 500 MB를 넘고 날짜 파티션이 있는 테이블을 쓰는 마트는 contract `load.mode`를 `incremental`로 고른다(결정 79, 인터뷰 고정 조회 "원천 크기와 날짜 파티션 확인")
  - 뷰(`__TABLES__.type` 2)는 테이블 정보의 크기로 판단하지 않는다. 날짜 파티션이 없어 `incremental`을 고를 수 없으므로, 쓸 컬럼만 읽는 dry-run 바이트가 500 MB 이하일 때만 쓴다
- [x] **운영 비용 상한**: 운영 DAG에는 쿼리 비용 상한이 아직 없다(동결 뒤 과제). 운영 실행 빈도와 예상 스캔량을 적었다
  - 예상 스캔량·빈도: 키트 범위 밖(운영 실행 없음)
