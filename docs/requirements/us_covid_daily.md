# 일별 전국 코로나 확진·사망 마트 요구서

## 1. 목적과 사용자
- 누가, 어떤 의사결정에 쓰는가: 분석가·기획자가 미국 전국의 누적 확진·사망과 일별 신규의 추이를 보고 현황을 보고하는 추세 모니터링에 쓴다(요청자 `requester1`)

## 2. 원천과 레이어
- 원천 테이블 (bigquery-public-data.covid19_nyt): `us_states`
- 원천 전제 (2026-11-13 원천 `INFORMATION_SCHEMA`와 dry-run 조회로 확인):
  - 갱신 방식: 과거 데이터. 마지막 날짜가 2023-03-23이라 새로 추가되지 않고, 변경(NYT 사후 정정으로 누적이 줄어든 행 409건)은 있다
  - 시간 컬럼: `date` DATE(보고일). 날짜 파티션·클러스터링 없음
  - 리전: US (`dags/harness_config.json`의 `source.location`과 같음)
  - 테이블 크기: 일반 테이블(뷰 아님), 61,942행, 전체 컬럼 dry-run 2,418,131 B(약 2.4 MB). 쿼리당 500 MB 이하
  - 컬럼: `date` DATE, `state_name` STRING, `state_fips_code` STRING, `confirmed_cases` INT64, `deaths` INT64 (NULL 0건, 음수 0건)
- 적재 방식 (contract `load`): `snapshot` (원천 2.4 MB로 500 MB 이하, 날짜 파티션 없음이라 기본안)
- 레이어: raw `raw_us_states`(신규) / stg `stg_us_states`(신규) / mart `mart_daily_us_covid`(신규). 재사용하는 상류 task 없음

## 3. 지표 정의
| 지표 | 계산식 | 단위 | 집계 기준일 | 제외 조건 |
|---|---|---|---|---|
| `cum_confirmed_cnt` 전국 누적 확진 | 같은 날 주·영토별 `confirmed_cases`의 합 | 건 | 보고일(`date`) | 없음, 정정 보정 안 함 |
| `cum_death_cnt` 전국 누적 사망 | 같은 날 주·영토별 `deaths`의 합 | 건 | 보고일(`date`) | 없음, 정정 보정 안 함 |
| `new_confirmed_cnt` 일별 신규 확진 | 전국 누적 확진 − 전일 누적 확진. 첫 날(2020-01-21)은 누적값 그대로 | 건 | 보고일 | 없음, 음수 그대로 둠 |
| `new_death_cnt` 일별 신규 사망 | 전국 누적 사망 − 전일 누적 사망. 첫 날은 누적값 그대로 | 건 | 보고일 | 없음, 음수 그대로 둠 |

비율 지표가 없어 SAFE_DIVIDE 대상은 없다.

## 4. 품질 기준 (ASSERT로 바꿀 수 있는 문장)
- raw에 당일 파티션 행이 있다
- stg의 (snapshot_date, report_date, state_fips_code)는 고유하고 누적 확진·사망은 NULL이 아니며 음수가 아니다
- mart의 report_date는 고유하고 누적 확진·사망은 NULL이 아니며 음수가 아니다
- 알려진 데이터 특성(ASSERT에 넣지 않음): 원천 정정으로 누적이 전일보다 줄어 일별 신규가 음수인 날이 있다(확진 3일 확인). 초기 일부 날짜는 보고 주가 1개뿐이다

## 5. 갱신 주기와 보관 기간
- 주 1회 snapshot 적재. 원천 전체를 복사해 전체 이력을 다시 집계한다
- 보관: mart 90일(`design_principles.md` §2 기본값). raw·stg 7일

## 9. 그레인·키, 가정, 범위 밖 (결정 42, 비면 L0 실패)
- 그레인(행 1개의 의미)과 키: mart는 전국 1일 1행, 키 (`snapshot_date`, `report_date`). raw·stg는 주(영토 포함)·일 1행, 키 (`snapshot_date`, 보고일, `state_fips_code`)
- 가정 목록 (AI가 스스로 채운 칸, 근거 쿼리 링크: 2026-11-13 원천 메타데이터·집계 조회, 데이터 값은 기록하지 않음):
  - 전국 = 원천의 56개 주·영토 전체의 합. 영토를 따로 빼지 않는다
  - 원천 기간 2020-01-21~2023-03-23, 1,158일, 날짜 간격 없음, (날짜, `state_fips_code`) 중복 0
  - 원천 정정은 보정하지 않고 알려진 데이터 특성으로 문서화(요청자 답변: 원천 그대로 합산, 음수 신규 그대로 둠)
  - 초기 날짜는 보고 주가 적어 전국 합계가 보고된 주만의 합이다
  - 원천이 2023-03-23 이후 갱신되지 않아 주 1회 적재로 충분하다
  - 컬럼 이름은 `design_principles.md` §6을 따라 `_date`, `_cnt` 접미사를 쓴다(`date` → `report_date`)
  - 개인 식별 컬럼 없음(`pii_columns.md` 검토 완료)
- 범위 밖 (이번에 하지 않을 것): 주별·카운티별 마트, 보고 주 수 컬럼, 인구 대비 비율, 정정 보정·7일 이동평균, 다른 원천 테이블 사용, 일별 스케줄 운영과 운영 데이터셋 적재
